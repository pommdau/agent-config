# agent-config

個人用AI設定をGitで管理する。スキルの実体はこのリポジトリに置き、利用先へスキル単位のsymlinkを作る。

## 構成と責務

- `rules/`：好み・記述方針・規約。関係する作業のときだけ読む。
- `skills/`：繰り返す手順。各フォルダが独立したスキル。
- `hooks/`：ツールのイベントに接続する処理。ツールごとに実装・検証して導入する。
- `scripts/`：リンク作成など、ユーザーやスケジューラが実行する管理処理。AIのHookとは分ける。

すべての規約を常時ロードする設定に詰め込まない。`rules/`に置くだけで自動適用されるわけではない。プロジェクトの指示やスキルから、必要なファイルだけを参照する。スキルを単独配布するときは必要な規約をスキル内に含め、別リポジトリへの暗黙の依存を避ける。

## スキルを使う

```sh
python3 scripts/link-skills.py --target "$HOME/.codex/skills"
python3 scripts/link-skills.py --target "$HOME/.codex/skills" --apply
```

初回は変更予定だけを表示する。`--apply`で反映する。同名の実フォルダや異なるリンクがあれば、変更せず停止する。既存のスキルを移行する場合は、実体の一致を確認してから既存フォルダを別の場所に退避し、実行する。`.system/`は対象外。削除済みスキルのリンクは自動削除しない。

リンクはこのリポジトリの絶対パスを参照する。別PCではcloneした場所で同じコマンドを実行する。リポジトリを移動した場合は古いリンクを確認・除去して作り直す。

## Gitでの運用

個人用の非公開リポジトリをremoteに設定する。変更内容を確認し、コミット・pushする。別PCではpullして、スキルの追加・削除がある場合はリンクも更新する。Gitへ記録するのはリンク先の実体。

定期バックアップは `scripts/backup.sh` で行う。remote `origin`と追跡ブランチを先に設定する。Git認証はGitの既存設定を使い、認証情報をここに保存しない。自動pull・マージ・強制pushは行わない。競合や送信失敗時は止まる。スケジュールは未設定。

## 管理対象外

`.system/`、認証情報、各ツールの履歴・キャッシュ・ログ、要約やデモなどの生成結果は保存しない。ユーザー全体の設定ファイルを丸ごとコピーしない。

## 設計の参考

[Roland Leth: Claude Code rules, hooks and skills, and how I set mine up](https://roland.leth.ro/blog/tech/claude-code-rules-hooks-and-skills-and-how-i-set-mine-up)

規約・手順・実行時の強制処理を分け、必要な情報だけ読み込む考え方を採用する。著者個人の権限設定やHookをそのまま移植するものではない。
